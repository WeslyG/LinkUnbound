## Зачем нужен LinkUnbound

Допустим, письма и рабочие чаты вы открываете в одном браузере, а личные сайты — в другом. Обычно все ссылки из почты, мессенджеров и документов открываются в одном системном браузере. LinkUnbound становится браузером по умолчанию и сначала проверяет ваши правила. Например, он может отправлять ссылки из Teams в рабочий профиль Chrome, а остальные — в Firefox.

Когда ни одно правило не подходит, можно оставить окно выбора браузера рядом с курсором или назначить **резервный браузер**, который откроется сразу. При включённом резервном браузере параметры показа окна выбора заблокированы с пояснением.

## Как начать

1. Установите LinkUnbound. В Windows скачайте файл `_x64-setup.exe` из [последнего релиза](https://github.com/WeslyG/LinkUnbound/releases/latest). На macOS используйте [установку через Homebrew](#установка-на-macos).
2. Назначьте LinkUnbound браузером по умолчанию в системных настройках.
3. Откройте настройки LinkUnbound. Добавьте правило для нужного сайта, адреса или приложения и выберите браузер или профиль. При желании назначьте резервный браузер.

В этом форке добавлен **русский интерфейс**. При первом запуске LinkUnbound использует язык системы, если он поддерживается, и английский в остальных случаях. Язык можно сменить в выпадающем списке настроек. Доступны русский, английский, испанский и автоматический режим.

## Установка на macOS

На macOS 13 и новее установите LinkUnbound из [нашего Homebrew tap](https://github.com/WeslyG/homebrew-tap). Homebrew сам выберет сборку для Apple Silicon или Intel.

```sh
brew install --cask weslyg/tap/weslyg-linkunbound
```

Откройте **LinkUnbound** из папки **Программы**. Сборка подписана локальной подписью ad hoc и не заверена Apple. Если macOS сообщит, что разработчик не подтверждён, закройте предупреждение. В течение часа откройте **Системные настройки → Конфиденциальность и безопасность**, нажмите **Всё равно открыть** рядом с сообщением о LinkUnbound и подтвердите запуск. Это разрешение относится к LinkUnbound. [Инструкция Apple](https://support.apple.com/ru-ru/102445)

Чтобы ссылки из других приложений шли через LinkUnbound, выберите его в разделе **Системные настройки → Рабочий стол и Dock → Веб-браузер по умолчанию**. Если включили запуск при входе и macOS его заблокировала, проверьте разрешение для LinkUnbound в **Системные настройки → Основные → Объекты входа**.

Для обновления используйте `brew update`, затем `brew upgrade --cask weslyg/tap/weslyg-linkunbound`. Если устанавливаете вручную, скачайте DMG из [последнего релиза](https://github.com/WeslyG/LinkUnbound/releases/latest), выберите `aarch64` для Apple Silicon или `x86_64` для Intel и перетащите LinkUnbound в **Программы**. Первый запуск подтверждается тем же способом.

## Как направить сразу несколько сайтов в один браузер

Если у вас двадцать рабочих сайтов, создавать отдельное правило для каждого не нужно. Создайте **список доменов** — набор имён сайтов — и привяжите к нему одно правило. Например, внесите в список адреса рабочей почты и документации и направьте все сайты из списка в рабочий профиль. Условие **«домен не входит в список»** работает наоборот. Оно пригодится, если всё вне рабочего списка должно открываться в личном браузере.

В разделе **Списки доменов** можно выбрать отдельные подборки для России и Украины из [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) или добавить свои. У каждого списка видны источник и состояние локальной копии. Применение правил и разрешение на фоновое обновление включаются отдельно. Можно выбрать периодичность или обновить кеш вручную. Сохранённые копии работают без сети.

### Как добавить свой список

Вставьте имена сайтов вручную или укажите HTTPS-адрес текстового файла. Используйте текст в UTF-8 и пишите по одному имени сайта на строку. Строки с `#` можно использовать для комментариев.

```text
# Рабочая почта и документация
mail.example.org
docs.example.org
```

Запись `docs.example.org` совпадёт и с `team.docs.example.org`. Вариант `.docs.example.org` с точкой в начале совпадёт только с поддоменами. Указывайте имя сайта без `https://`, пути или маски вроде `*.docs.example.org`. LinkUnbound проверяет записи при добавлении и обновлении.

Адрес и содержимое своего списка можно менять с сохранением привязанных правил. При удалении приложение покажет, какие правила используют этот список, и предложит удалить их вместе с ним после подтверждения.

## Данные и обновления

Настройки, правила и кеш списков хранятся локально. В приложении нет телеметрии и функции формирования отчётов. LinkUnbound обращается к GitHub за обновлениями приложения и к указанным источникам при обновлении списков. Перед установкой обновления он проверяет подпись и номер версии.

## Выпуск новой версии

Добавьте непустой раздел `## [X.Y.Z] - ГГГГ-ММ-ДД` в [CHANGELOG.md](CHANGELOG.md) и отправьте тег `vX.Y.Z`. [GitHub Actions](.github/workflows/windows-release.yml) собирает Windows x64 и обе версии macOS, подписывает файлы ключом Tauri, публикует установщики и переносит текст этого раздела в описание релиза. Затем обновляется ветка `manifest`. Ручной запуск позволяет проверить артефакты без публикации.

На macOS приложение обновляется через Homebrew или переустановкой из DMG. Встроенное автообновление требует нотариализации Apple.
